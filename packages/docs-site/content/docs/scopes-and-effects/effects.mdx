Use this page when you know a TypeScript method or PDXScript key and need to find its exact
signature and legal scopes. For the opposite lookup, open a page under **Scopes** to see everything
available on one generated scope interface.

The list contains one canonical entry for every method in the current SDK script-reference model:

- **Effect** entries are ordinary generated effect methods.
- **Structural** entries record control flow, iteration, saved targets, or other script structure.
- **Event fire** entries record typed event fires. **Availability** says where the fire call is
  legal; **Event body scope** says where the fired event runs.

Availability is either universal or an explicit scope list. Universal methods share one expandable
scope-page list instead of repeating the same links in every row. Scope-specific availability links
each published scope page directly.

Each entry has a stable `#effects-methodName` anchor. For example,
[`#effects-addResource`](#effects-addResource) opens `addResource` even when filtering or paging is
active. The browser view uses client JavaScript for filtering, paging, and deep-link focus. Agents
that request the Markdown representation receive the complete inventory as one unpaginated table.

Scope-link properties are not effects. They navigate to another scope and appear under **Outgoing
scope transitions** on each scope page.

This is the SDK-supported authoring surface, not an exhaustive list of live-game effects. Its rows
come from the SDK's post-overlay generated records and the reviewed reference records owned by
handwritten structural methods.
