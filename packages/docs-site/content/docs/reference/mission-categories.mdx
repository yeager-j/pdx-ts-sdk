A **mission category** groups missions and supplies their default map and
situation-log presentation. The SDK writes category definitions under
`common/missions/mission_categories/`.

## Ordinary categories and contract categories

`isContract` is required and changes which mission fields are valid. A category
with `isContract: false` accepts ordinary missions. A category with
`isContract: true` is a contract category; passing its returned reference to
`mod.mission(...)` requires an `eventChain` and enables contract-only fields
such as issuer and operator checks, acceptance and completion time limits,
`onIssue`, `onAccept`, and `aiWeight`.

Keep the returned category item instead of reducing it to a raw id. Its literal
`isContract` value is the evidence the SDK uses to select the correct mission
contract.

```ts
const researchContracts = mod.missionCategory("research_contract", {
  name: "Research Contracts",
  isContract: true,
  mapIcon: vanilla.spriteType("GFX_nomad_contract_science_icon"),
  logIcon: "gfx/interface/icons/contracts/science_contract_icon_log.dds",
  showInIssueList: true,
});
```

`mapIcon` is a sprite reference used on the galactic map. `logIcon` is a file
path used by the situation log. `showInIssueList` controls whether a contract
category appears in the issue-contract interface; Vanilla uses it on contract
categories and leaves it disabled by default.

If a mission omits `category`, Stellaris uses the first loaded mission category.
That makes behavior depend on load order, so assign a category explicitly.
See [Missions](/reference/missions/) for the complete ordinary and contract
lifecycle.

There is no `mod.patchMissionCategory` surface. The SDK checks the definition
shape, owned references, localization, and emitted path, but it does not verify
icon layout or contract-interface placement. Test both the map and situation
log in Stellaris.
