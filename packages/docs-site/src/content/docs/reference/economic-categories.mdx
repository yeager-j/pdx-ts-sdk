An **economic category** classifies resource costs, production, upkeep, or
logistics. Stellaris uses the category hierarchy for AI budgets and to generate
modifier keys that can change those transactions. The SDK writes categories
under `common/economic_categories/`.

Start with [Economic modifiers](/concepts/economic-modifiers/) for the complete
flow from a resource transaction to a generated modifier key and its value.

`generateAddModifiers` and `generateMultModifiers` accept `cost`, `produces`,
`upkeep`, and `logistics`. Each entry asks Stellaris to generate that family of
modifier keys for the category. It does not assign a resource transaction to
the category or give any modifier a value.

`modifierCategory` classifies the game objects on which the generated modifier
values can be read and applied. Stellaris also uses that classification to
filter irrelevant modifiers. `useForAiBudget` tells the AI to track the
category as part of its resource budget. Treat these as separate choices: a
category can generate modifiers without being an AI budget category.

## Use parents for shared economic behavior

`parent` builds a category hierarchy. Vanilla's `edicts` category inherits
from `country`, adds cost and upkeep multiplier families, and lets the AI use
the parent budget for energy and food upkeep. Its `edicts_unscaled` child then
changes only the tooltip scaling behavior.

Use the item returned by `mod.economicCategory` when the parent is defined in
the same mod. Use `vanilla.economicCategory(...)` for a checked vanilla parent.
A raw string is available for a category owned by another mod, but the SDK
cannot check that it exists.

`hidden: true` and `icon` belong to different game-defined category forms. The
generated TypeScript interface does not make them mutually exclusive, so do
not set both on one definition.

## Triggered blocks redirect selected modifiers

The four `triggered*Modifier` fields add repeated conditional blocks for cost,
production, upkeep, or logistics. Each row names another economic category in
`key`, selects `add`, `mult`, or both in `modifierTypes`, and can include a
`trigger`.

Vanilla's worker and specialist job categories use
`triggeredProducesModifier` to redirect production multipliers to the matching
drone category for gestalt owners. The `key` is an economic-category id, not a
resource id. Start from a current vanilla category with the same relationship
and preserve its trigger scope.

<Aside type="caution" title="The trigger scope is unchecked">
  The generated contract does not encode which game object evaluates these blocks. It accepts a
  trigger without checking that scope. Verify the trigger's legal runtime scope and the generated
  modifier values in Stellaris.
</Aside>

Test every consumer that selects the category, generated additive and
multiplicative modifiers, parent behavior, AI budgeting, tooltips, conditional
redirection, and save/load in Stellaris. See
[Testing your mod](/guides/testing-your-mod/).
