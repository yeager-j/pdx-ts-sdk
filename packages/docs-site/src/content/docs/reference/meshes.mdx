A **pdxmesh** registers a `.mesh` model with optional material settings and
animation bindings. The SDK writes definitions under `gfx/models/` in a `.gfx`
file with an `objectTypes` envelope.

## Register a model file

Put the model and its related files in the scaffolded `assets/` directory. The
[Assets](/concepts/assets/) page explains how that directory maps to the mod
root and how the Fold checks Asset paths.

<PairedExample name="meshes" />

`file` is a mod-root Asset path. It accepts a plain string or an
`AssetFileItem`. The texture members inside `meshsettings` are different:
Stellaris writes them as bare file names such as `relay_diffuse.dds`, so the
SDK preserves those strings without an Asset-path check.

Each `meshsettings` row can select a shape by `name` or `index`, then set its
shader and texture files. Each `animation` row connects an animation `id` to a
model-animation label. The SDK does not check the `type` label because the
corresponding `model_animation` definition lives in an opaque `.asset` file.
Ship that descriptor through the same [Assets](/concepts/assets/) pipeline.

## Keep the engine label compatible with external files

The default call mints `<prefix>_<name>` with no registry segment. The example
therefore produces `starfall_relay_mesh`.

Use `{ prefix: false }` only when an existing `.asset` or entity definition
requires a complete label in another shape:

```ts
mod.pdxmesh(
  "Relay_starfall_mesh",
  { file: "gfx/models/starfall/relay.mesh" },
  { prefix: false }
);
```

The complete name must still contain `starfall` as a whole `_`-delimited
segment. It may appear at the start, inside, or at the end. This keeps the
definition owned by the mod even when the SDK does not prepend the prefix.

## API and vanilla references

- [`PdxmeshDef`](https://github.com/yeager-j/pdx-ts-sdk/blob/main/packages/sdk/src/generated/pdxmesh.ts)
  is the generated definition used by `mod.pdxmesh`.
- [`vanilla.pdxmesh`](https://github.com/yeager-j/pdx-ts-sdk/blob/main/packages/sdk/src/generated/vanilla-refs.ts)
  provides checked references to vanilla mesh ids.

Meshes have no patch surface. `mod.patchPdxmesh` does not exist.
