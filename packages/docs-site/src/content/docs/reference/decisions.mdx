A **decision** is an action presented on a planet or ship. Its definition can
control availability, resource cost, queue behavior, and the effect that runs
when it completes. The SDK writes definitions under `common/decisions/`.

`potential` controls whether the decision is shown and `allow` controls whether
it can be selected. `abortTrigger`, `abortEffect`, `onQueued`, and `onUnqueued`
support longer actions that use `enactmentTime`. The example is immediate and
uses `allow` to prevent the same temporary modifier from being applied again.

## Choose planet or ship scope

Set `scope: "ship"` for a ship decision. The `scope` member is an authoring hint:
it changes which triggers and effects TypeScript accepts but emits no
PDXScript. Omit it for a planet decision.

The rules allow both scopes but do not identify the runtime mechanism that
makes a particular definition a ship decision. Verify ship decisions and all
queue behavior in Stellaris before relying on them.

## API and vanilla references

- [`DecisionDef`](https://github.com/yeager-j/pdx-ts-sdk/blob/main/packages/sdk/src/generated/decision.ts)
  is the generated definition used by `mod.decision`.
- [`vanilla.decision`](https://github.com/yeager-j/pdx-ts-sdk/blob/main/packages/sdk/src/generated/vanilla-refs.ts)
  provides checked references to vanilla decision ids.

Decisions have no patch surface. `mod.patchDecision` does not exist.
